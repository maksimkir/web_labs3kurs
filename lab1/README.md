# Лабораторна робота №1
**Тема:** Строга типізація у вебі: екосистема мови TypeScript

## Структура проєкту

```
lab1/
├── package.json
├── tsconfig.json
├── README.md
├── src/
│   ├── variables.ts   — Завдання 2 (змінні, масиви)
│   ├── functions.ts   — Завдання 2 (функція з параметром за замовчуванням)
│   ├── icecream.ts    — Завдання 3 (розрахунок вартості морозива)
│   ├── animals.ts     — Завдання 4 (інтерфейс Animal, Cat/Bird/Fish)
│   ├── shapes.ts      — Завдання 5 (інтерфейс Shape, Circle/Rectangle/Triangle)
│   ├── cars.ts        — Завдання 6 (абстрактний клас Car, Toyota/BMW/Tesla)
│   ├── employees.ts   — Завдання 7 (абстрактний клас Employee, Developer/Manager)
│   ├── courses.ts     — Завдання 8 (Course, OnlineCourse, CourseManager)
│   └── library.ts     — Завдання 9 (LibraryItem, Book/Magazine/DVD, Library)
└── dist/              — скомпільовані .js файли (генеруються командою build)
```

## Завдання 1. Налаштування середовища

1. **Встановлення Node.js.** Завантажити LTS-версію з https://nodejs.org/en та встановити.
   Перевірка: `node -v` та `npm -v`.

2. **Ініціалізація проєкту:**
   ```bash
   mkdir lab1 && cd lab1
   npm init -y
   ```
   Це створює файл `package.json`.

3. **Встановлення TypeScript:**
   ```bash
   npm install -g typescript          # глобально (для команди tsc у будь-якому місці)
   npm install --save-dev typescript  # локально в проєкт
   npm install --save-dev @types/node # типи для Node.js API
   ```

4. **Ініціалізація TypeScript у проєкті:**
   ```bash
   npx tsc --init
   ```
   Це створює файл `tsconfig.json` з базовими налаштуваннями.

5. **Налаштування компілятора (`tsconfig.json`)** — ключові опції, використані в цьому проєкті:
   - `target: "ES2020"` — версія JS, у яку компілюється код;
   - `module: "CommonJS"` — система модулів для Node.js;
   - `rootDir: "./src"` / `outDir: "./dist"` — де лежать вихідні файли й куди складати результат;
   - `strict: true` — увімкнення всіх суворих перевірок типів;
   - `esModuleInterop: true` — сумісність з CommonJS-модулями;
   - `sourceMap: true` — генерація .map файлів для відлагодження.

### Команди для роботи з проєктом

```bash
npm install       # встановити залежності (typescript, @types/node, readline-sync)
npm run build     # скомпілювати всі .ts файли з src/ у dist/
npm run watch     # компіляція в режимі спостереження за змінами
node dist/variables.js   # запустити конкретний скомпільований файл
```

## Контрольні запитання

**1. Що таке TypeScript і які його основні переваги порівняно з JavaScript?**
TypeScript — це надбудова (суперсет) над JavaScript, розроблена Microsoft, яка додає статичну типізацію та компілюється у звичайний JavaScript. Переваги: виявлення помилок ще на етапі написання коду (до запуску), кращий автодопомога (автодоповнення, підказки) в IDE, легша підтримка й рефакторинг великих проєктів, підтримка сучасних можливостей ООП (інтерфейси, дженерики, enum).

**2. Як налаштувати середовище для розробки TypeScript? Назвіть основні кроки.**
Встановити Node.js → ініціалізувати проєкт (`npm init`) → встановити TypeScript (`npm install typescript`) → створити конфігурацію (`npx tsc --init`) → налаштувати `tsconfig.json` → писати код у `.ts` файлах і компілювати командою `tsc`.

**3. Що таке файл tsconfig.json і яку роль він відіграє в проєкті TypeScript?**
Це конфігураційний файл, який визначає, які файли включати в компіляцію та з якими параметрами (версія JS, суворість перевірки типів, шляхи вхідних/вихідних файлів тощо). Він дозволяє не вказувати ці параметри щоразу вручну в командному рядку.

**4. Які основні типи даних підтримує TypeScript? Дайте короткий опис кожного типу.**
- `string` — текстові значення;
- `number` — усі числа (цілі й дробові);
- `boolean` — логічне значення true/false;
- `any` — будь-який тип, вимикає перевірку типів;
- `unknown` — безпечніший аналог any, вимагає перевірки типу перед використанням;
- `void` — відсутність значення, що повертається функцією;
- `null` / `undefined` — відсутність значення;
- `object`, масиви (`T[]`), кортежі (`tuple`), `enum`, а також union/intersection типи.

**5. Чим відрізняється let від var?**
`let` має блочну область видимості (`{}`), не піддається "спливанню" (hoisting) з ініціалізацією і не дозволяє повторне оголошення в тій самій області видимості. `var` має функціональну область видимості, спливає з ініціалізацією `undefined` і дозволяє повторне оголошення — це часто призводить до помилок.

**6. Що таке тип any і коли його слід використовувати?**
`any` вимикає перевірку типів для змінної — вона може приймати значення будь-якого типу без помилок компіляції. Використовувати варто вкрай обмежено: наприклад, під час поступової міграції JS-коду на TypeScript або коли тип дійсно невідомий заздалегідь і не піддається типізації.

**7. Як можна визначити власний тип даних у TypeScript? Наведіть приклад.**
За допомогою ключових слів `type` або `interface`:
```typescript
type Point = { x: number; y: number };
interface Point2 { x: number; y: number; }
```

**8. Як компілювати файли TypeScript у JavaScript? Яка команда для цього використовується?**
Командою `tsc назва_файлу.ts` для одного файлу або просто `tsc`, якщо є `tsconfig.json` — тоді компілюються всі файли, вказані в конфігурації.

**9. Що таке --watch режим компілятора TypeScript і як він може бути корисний?**
Режим `tsc --watch` запускає компілятор у фоновому режимі: він стежить за змінами у файлах і автоматично перекомпільовує їх при збереженні, що прискорює розробку, бо не потрібно вручну запускати компіляцію щоразу.

**10. Які опції можна вказати у файлі tsconfig.json для налаштування процесу компіляції? Назвіть принаймні три з них.**
`target` (версія JS), `module` (система модулів), `outDir` (папка виводу), `rootDir` (коренева папка вихідних файлів), `strict` (сувора перевірка типів), `sourceMap` (генерація map-файлів).

**11. Для чого застосовуються map-файли?**
Source map (`.map`) файли зв'язують скомпільований JavaScript-код з оригінальним TypeScript-кодом, що дозволяє під час відлагодження в браузері чи Node.js бачити й ставити точки зупину саме в `.ts` файлах, а не в згенерованому JS.

**12. Яким чином можна оголосити змінну з конкретним типом даних у TypeScript? Наведіть приклад.**
```typescript
let age: number = 25;
let city: string = "Київ";
```

**13. Що таке типи масивів у TypeScript і як їх правильно оголосити?**
Це спосіб вказати, елементи якого типу може містити масив. Оголошуються як `тип[]` або `Array<тип>`:
```typescript
let numbers: number[] = [1, 2, 3];
let names: Array<string> = ["Анна", "Іван"];
```

**14. Які основні відмінності між типами number і any в TypeScript?**
`number` обмежує змінну лише числовими значеннями — компілятор видасть помилку при спробі присвоїти рядок чи інший тип. `any` знімає будь-які обмеження — змінній можна присвоїти значення будь-якого типу без перевірки компілятором.

**15. Як оголосити функцію у TypeScript з типами параметрів та типом повернення? Наведіть приклад.**
```typescript
function add(a: number, b: number): number {
  return a + b;
}
```

**16. Що таке параметри за замовчуванням у функціях TypeScript і як їх використовувати?**
Це значення, які параметр отримує автоматично, якщо аргумент не переданий під час виклику функції:
```typescript
function greet(name: string, greeting: string = "Привіт"): void {
  console.log(`${greeting}, ${name}!`);
}
```

**17. Що таке функція, яка повертає void, і в яких випадках її слід використовувати?**
`void` означає, що функція не повертає жодного значення (використовується для побічних ефектів — виводу в консоль, зміни стану тощо). Використовується, коли результат виконання функції не потрібен викликаючому коду.

**18. Для чого використовується метод call, apply?**
Обидва методи дозволяють викликати функцію з явно заданим контекстом `this`. `call(thisArg, arg1, arg2, ...)` передає аргументи через кому, а `apply(thisArg, [arg1, arg2, ...])` — масивом аргументів.

**19. Як у TypeScript реалізовано наслідування?**
За допомогою ключового слова `extends`: клас-нащадок успадковує властивості й методи батьківського класу, а через `super(...)` викликає конструктор батьківського класу:
```typescript
class Animal { }
class Dog extends Animal { }
```

**20. Що таке абстрактний клас? Абстрактний метод?**
Абстрактний клас (`abstract class`) — це клас, від якого не можна створити екземпляр напряму; він служить базою для успадкування. Абстрактний метод (`abstract method`) оголошується без реалізації в абстрактному класі й зобов'язує кожен похідний клас надати власну реалізацію.

**21. Навіщо використовується ключове слово implements?**
Воно вказує, що клас зобов'язується реалізувати всі властивості та методи, описані в певному інтерфейсі. Це забезпечує відповідність класу заданому контракту.

**22. У чому різниця між private і protected?**
`private` — властивість/метод доступні лише всередині класу, де їх оголошено (навіть нащадки не мають доступу). `protected` — доступні всередині класу та в усіх його нащадках, але недоступні ззовні класу.

**23. Навіщо використовується ключове слово static? readonly?**
`static` позначає властивість або метод, що належить самому класу, а не його екземплярам (викликається через назву класу). `readonly` позначає властивість, значення якої можна встановити лише один раз (при оголошенні або в конструкторі), після чого змінити його неможливо.

**24. Що таке опціональні параметри в інтерфейсі?**
Це властивості чи методи інтерфейсу, позначені знаком `?`, наявність яких у об'єкті/класі, що реалізує інтерфейс, не є обов'язковою:
```typescript
interface User {
  name: string;
  age?: number; // опціональна властивість
}
```

**25. Навіщо використовується конструктор у класі?**
Конструктор — це спеціальний метод, який автоматично викликається під час створення нового екземпляра класу (`new`). Він використовується для ініціалізації властивостей об'єкта початковими значеннями.
