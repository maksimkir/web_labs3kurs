# Study Planner — лабораторна робота №8

**Тема:** React Fundamentals: компоненти, JSX, props, стан, події та списки.

Простий планувальник навчальних завдань: список завдань, додавання, позначення виконаним,
видалення, фільтр «Всі / Виконані / Не виконані» і статистика. Дані зберігаються лише в пам'яті
React (`useState`), після перезавантаження сторінки повертаються початкові завдання.

Стек: **React 19 + TypeScript**, Vite, **SCSS + BEM**, ESLint.

## Запуск

Потрібен Node.js 22.22 або новіший.

```bash
npm install
npm run dev        # http://localhost:5173
npm run lint       # ESLint
npm run build      # перевірка типів + продакшн-збірка
```

```
│   └── TaskItem.tsx      # картка завдання з кнопками керування
```

Кожен компонент має власний SCSS-файл з одним BEM-блоком (`.task-item`, `.task-item__title`,
`.task-item--completed` тощо).

```
App (стан: tasks, filter, search, sortByPriority, theme)
├── Header         ← theme, onToggleTheme
├── TaskForm       ← onAdd
```

## Вимоги → де реалізовано

| Вимога | Де |
|---|---|
| Тип `Task` (id, title, description, completed, priority, category) | `types/task.ts` |
| Компоненти App, Header, TaskForm, TaskList, TaskItem, TaskFilters, TaskStats | `components/`, `App.tsx` |
| Взаємодія через props і callback-функції | `App.tsx` → `onAdd`, `onToggle`, `onDelete`, `onChange` |
| Список через `map` зі стабільним `key` | `TaskList.tsx` (`key={task.id}`) |
| Виконане завдання візуально відрізняється | `TaskItem.scss` (`.task-item--completed`) |
| Форма: назва обов'язкова, очищення після додавання | `TaskForm.tsx` |
| Виконано ↔ не виконано, видалення, immutable update | `App.tsx` (`map`, `filter`, spread) |
| Фільтр без зміни вихідного масиву, активний фільтр виділено | `App.tsx` (`visibleTasks`), `TaskFilters.tsx` |
| Статистика без окремого state | `TaskStats.tsx` (`filter().length`) |
| Умовний рендеринг: порожній список і порожній фільтр | `TaskList.tsx` |
| Без `alert` | помилки виводяться під полем форми |

## Відповіді на контрольні запитання

**1. Що таке React-компонент і чому інтерфейс будується з компонентів?**
Функція, яка приймає props і повертає JSX — опис частини інтерфейсу. Компоненти можна
перевикористовувати, тестувати й змінювати окремо; великий інтерфейс складається з малих
зрозумілих частин (`TaskItem` — одна картка, `TaskList` — список карток).

**2. Що таке JSX і чим він відрізняється від HTML?**
Синтаксис JavaScript, схожий на HTML, який компілюється у виклики React. Відмінності: `className`
замість `class`, `htmlFor` замість `for`, атрибути в camelCase (`onClick`), вирази в `{}`, усі теги
закриваються (`<input />`), стилі — об'єкт (`style={{ width: '50%' }}`).

**3. Чому JSX повинен повертати один кореневий елемент або Fragment?**
JSX перетворюється на виклик функції, а функція повертає одне значення. Кілька елементів
обгортають у спільний тег або у Fragment `<>...</>`, який не додає зайвого вузла в DOM.

**4. Як у JSX вставляється JavaScript-вираз?**
У фігурних дужках: `{task.title}`, `{PRIORITY_LABELS[task.priority]}`, `{tasks.length}`,
`className={...}`.

**5. Що таке props? Як вони передаються від батьківського компонента до дочірнього?**
Параметри компонента — як атрибути: `<TaskItem task={task} onToggle={toggleTask} />`. Дочірній
компонент отримує їх як об'єкт: `function TaskItem({ task, onToggle }: TaskItemProps)`.

**6. Чи може дочірній компонент напряму змінювати props? Як правильно передати callback?**
Ні, props тільки для читання. Батько передає функцію (`onToggle={toggleTask}`), дочірній її
викликає (`onClick={() => onToggle(task.id)}`), а змінює стан сам батько.

**7. Для чого використовується `useState`? Що повертає цей hook?**
Для локального стану компонента, зміна якого перерендерює компонент. Повертає пару
`[значення, setter]`: `const [tasks, setTasks] = useState<Task[]>(initialTasks)`.

**8. Чому не слід напряму змінювати масив або об'єкт у state?**
React порівнює посилання: якщо змінити той самий масив (`tasks.push(...)`), посилання не
зміниться, і React може не перерендерити компонент. Крім того, мутація ламає передбачуваність
стану. Потрібно створювати нову копію.

**9. Різниця між `setState(value)` і `setState(prev => ...)`?**
`setState(value)` встановлює конкретне значення. `setState(prev => ...)` обчислює нове значення
з найсвіжішого попереднього — це надійно, коли новий стан залежить від старого або кілька
оновлень відбуваються поспіль (`setTasks(prev => prev.filter(...))`).

**10. Як React рендерить список через `map`?**
`map` перетворює масив даних на масив JSX-елементів:
`tasks.map((task) => <TaskItem key={task.id} task={task} />)`.

**11. Для чого потрібен `key`? Чому індекс масиву як key може бути проблемним?**
`key` допомагає React зіставити елементи між рендерами й оновити лише змінені. Індекс змінюється
при додаванні на початок, видаленні чи сортуванні — React переплутає елементи (неправильний стан
полів, зайві перерендери). Потрібен стабільний унікальний id.

**12. Що таке умовний рендеринг? Способи реалізації.**
Показ різного JSX залежно від умови: `if` з раннім `return` (порожній список у `TaskList`),
тернарний оператор `{task.completed ? 'Повернути' : 'Виконано'}`, `&&`
(`{titleError && <span>...</span>}`), умовний клас.

**13. Чим відрізняється локальний state від props?**
State належить компоненту й змінюється ним самим через setter. Props приходять ззовні від батька
і в компоненті доступні лише для читання.

**14. Де доцільно зберігати state, який використовується кількома дочірніми компонентами?**
У найближчому спільному батьківському компоненті («підняття стану»). Тут `tasks` і `filter`
зберігаються в `App`, бо їх використовують `TaskList`, `TaskStats` і `TaskFilters`.

**15. Що відбудеться після виклику setter-функції з `useState`?**
React запланує оновлення, перерендерить компонент з новим значенням (і його дочірні) та оновить
лише змінені частини DOM. Значення змінної в поточному рендері не змінюється одразу.

**16. Чому статистику не обов'язково зберігати в окремому state?**
Вона повністю обчислюється з `tasks` (`tasks.filter(t => t.completed).length`). Окремий state
дублював би дані й міг розсинхронізуватися; похідні значення рахують під час рендеру.

**17. Що означає immutable update і як він застосовується до масивів у React?**
Оновлення без зміни існуючих даних: створюється новий масив/об'єкт. Додавання —
`[newTask, ...prev]`, видалення — `prev.filter(...)`, зміна —
`prev.map(t => t.id === id ? { ...t, completed: !t.completed } : t)`, сортування — копія
`[...tasks].sort(...)`.
